# Первый запуск: Antminer S9 control board

Практическая инструкция для **этапа 0** — boot mode, снятие boot log, первое включение и проверка штатной прошивки.

Плата: **Antminer S9 control board**, кристалл **XC7Z010** (Zynq-7010).  
Связанные документы: [ZYNQ7000 — туториал](ZYNQ7000%20-%20туториал.md) (этап 0), [чек-лист прошивки](ZYNQ7000%20-%20чек-лист%20прошивки.md).  
Локальный сборник артефактов: `sample_s9/` (эталонные логи, схемы, pinout).

Цепочка загрузки Zynq:

```
Boot ROM → FSBL → [bitstream] → U-Boot → [Linux / приложение]
```

---

## Boot mode: что это и зачем

При **сбросе или включении** Zynq считывает уровни на выводах **MODE[2:0]** (strap pins) и выбирает **один** источник первой стадии загрузки. Это не «режим работы» платы, а ответ на вопрос: **откуда Boot ROM возьмёт FSBL** (или передаст управление JTAG).

На S9 режим задаётся **джамперами JP1–JP4**. Таблица и иллюстрации:

| Файл | Содержимое |
|------|------------|
| `sample_s9/boot_mode/boot_jumpers.txt` | Таблица JP1–JP4 |
| `sample_s9/boot_mode/boot_select.png` | Фото/разметка джамперов |
| `sample_s9/boot_mode/boot_mode.png` | Доп. иллюстрация (astranome) |

### Режимы на S9

| Режим | JP1 JP2 JP3 JP4 | Что происходит | Когда нужен |
|-------|-------------------|----------------|-------------|
| **NAND** | 0 1 0 0 | Boot ROM → FSBL с **NAND flash** (256 MB на плате) | **Штатный майнер** — заводская прошивка |
| **SD** | 0 1 0 1 | Boot ROM → загрузка с **microSD** (обычно `BOOT.BIN` на FAT) | **Своя разработка** без переписывания NAND |
| **JTAG** | 0 0 0 0 | Boot ROM → управление через **JTAG** | Прошивка/отладка в Vivado, `petalinux-boot --jtag` |
| **QSPI** | 0 0 0 1 | Загрузка с **QSPI flash** | Редко в dev-сценариях на S9 |
| **NOR** | 0 0 1 0 | Загрузка с **NOR flash** | Редко; на майнерской плате не основной путь |

`0` = джампер **снят**, `1` = **замкнут**. Таблица из [MelodyCoin/eSnyne](https://github.com/MelodyCoin/eSnyne) — **сверьте с фото** на своей ревизии платы.

### Важные правила

1. **Режим фиксируется при включении.** Сменили джамперы — **полностью обесточьте** плату и включите снова.
2. **Режимы взаимоисключающие** — активен только один набор strap-пинов.
3. **Штатный эталон:** в `sample_s9/boot/bootlog_stock_nand.log` первая строка FSBL после инициализации: `Boot mode is NAND`.
4. **Для первого знакомства** логично оставить **NAND** (ничего не менять) и убедиться, что штатная прошивка жива. Для своего Linux позже переключите на **SD**.
5. Таблица eSnyne также упоминает T9+/E3 — для **конкретной S9** ориентир: ваше фото + строка `Boot mode is …` в сохранённом логе.

### Сравнение с EBAZ4205

| | EBAZ4205 | Antminer S9 |
|--|----------|-------------|
| Boot mode | Резисторы R2577 / R2584 (пайка) | Джамперы JP1–JP4 |
| Штатный носитель | NAND | NAND |
| SD-слот | Часто нужно припаять | Уже на плате |
| UART / JTAG | Часто нужна пайка | Обычно уже на плате |

## Boot log: что это и как снять

**Boot log** — текст с **UART-консоли** от включения питания до login, shell или работы приложения. Это эталон для сравнения: размер DDR, видимость NAND/SD, версии FSBL/U-Boot/Linux, `bootargs`, ошибки.

Эталон в репозитории:

| Файл | Назначение |
|------|------------|
| `sample_s9/boot/bootlog_stock_nand.log` | Полный лог штатной прошивки (NAND → bmminer) |
| `sample_s9/boot/bootlog_notes.txt` | Краткая выжимка |
| `sample_s9/boot/uboot_bitmain-antminer-s9.dts` | Ожидаемая периферия PS (polprog) |

### Что нужно для снятия лога

| Компонент | Назначение |
|-----------|------------|
| USB-UART (FTDI, CP2102, CH340) | Консоль процессора PS |
| Провода 3.3 V | TX, RX, GND к UART-разъёму платы |
| Блок питания | См. `sample_s9/scheme/pinout_supplements/power_pin.png` |
| ПК | Терминал с записью в файл |

Параметры консоли штатной прошивки S9: **115200, 8N1, без flow control**, устройство **`ttyPS0`** (видно в boot log: `console=ttyPS0,115200`).

### Пошагово

**1. Подключить UART**

- GND адаптера → GND платы.
- TX адаптера → RX платы, RX адаптера → TX платы (перекрёстно).
- Уровни **3.3 V** (не 5 V).

Разъёмы и пины: схема `sample_s9/scheme/AntMiner_ControlBoard_XC7010_V1.01.pdf`, карты в `sample_s9/pinout/` и `sample_s9/scheme/pinout_supplements/`.

**2. Выставить boot mode**

- Штатная прошивка: **NAND** (0 1 0 0).
- Своя SD-карта (позже): **SD** (0 1 0 1), карта вставлена.

**3. Открыть терминал на ПК**

PuTTY, MobaXterm или minicom (Linux/WSL):

```bash
minicom -D /dev/ttyUSB0 -b 115200
```

Windows (PowerShell, замените `COM3`):

```powershell
$port = New-Object System.IO.Ports.SerialPort COM3,115200,None,8,one
$port.Open()
while ($true) { if ($port.BytesToRead) { Write-Host -NoNewline $port.ReadExisting() } }
```

Включите **запись в файл** до подачи питания (в PuTTY: *Session → Logging*).

**4. Включить питание**

Порядок: UART и терминал готовы → **затем** питание платы. В логе должны появиться сообщения FSBL, U-Boot, Linux.

**5. Сохранить лог**

Сохраните в свой файл (например `my_bootlog_nand.txt`) и сравните с `bootlog_stock_nand.log`.

### На что смотреть в логе

| Строка / факт | Значение |
|---------------|----------|
| `Boot mode is NAND` / `SD` | Совпали джамперы с ожиданием |
| `DRAM: 496 MiB` / `512 MB` | DDR инициализирована |
| `NAND: 256 MiB` | NAND flash видна |
| `MMC: zynq_sdhci` | SD-контроллер виден |
| `Gem.e000b000` | Ethernet на уровне U-Boot |
| `Linux version 3.14…` | Ядро стартовало |
| `bmminer` | Штатное ПО майнера запущено |
| Тишина или «мусор» | Неверный COM, TX/RX, GND или скорость |

### Дампы `/proc` (когда Linux уже загрузился)

В репозиториях S9 готовых дампов почти нет (на EBAZ4205 есть в xjtuecho). Снимите сами — по UART в shell или по сети, если штатный Linux поднял Ethernet:

```bash
cat /proc/cpuinfo
cat /proc/version
cat /proc/cmdline
cat /proc/partitions
cat /proc/mtd
mount
dmesg | head -100
```

Сохраните вывод — это ваш эталон разметки NAND и окружения **до** любых экспериментов с прошивкой.

## Первое включение: чек-лист

### До включения

1. **Питание** — изучить `power_pin.png` и PDF-схему; не путать линии питания вентиляторов (12 V) и логики.
2. **Плата отдельно** — control board можно проверять без хеш-плат; разъёмы DATA для boot log не обязательны.
3. **Джамперы** — для первого раза **NAND**.
4. **UART** — подключён, терминал 115200 открыт, логирование включено **до** питания.
5. **JTAG** — на первое включение не обязателен (нужен позже для Vivado).
6. **SD-карта** — может быть вставлена; при режиме NAND загрузка всё равно с NAND.

### Безопасный сценарий первого включения

```
1. UART → ПК, терминал 115200, запись лога в файл
2. JP1–JP4 → NAND (штатный режим)
3. Подать питание
4. Наблюдать лог 1–3 минуты
5. Обесточить
6. Сохранить лог, сравнить с sample_s9/boot/bootlog_stock_nand.log
```

### Признаки «плата жива»

- FSBL печатает версию Xilinx.
- Определяется DRAM (обычно ~496–512 MiB на типичной S9).
- Видны NAND и/или MMC.
- U-Boot доходит до autoboot или грузит ядро.
- Linux и штатное ПО (bmminer) стартуют без критических ошибок DDR/NAND.

### Типичные проблемы

| Симптом | Возможная причина |
|---------|-------------------|
| Полная тишина в UART | Неверные TX/RX, нет GND, неверный COM-порт |
| Нечитаемые символы | Неверная скорость (должно быть 115200) |
| FSBL и останов | Неверный boot mode, пустая/повреждённая NAND |
| Ошибка DDR | Неисправность памяти или другая ревизия (256 vs 512 MB, C41 1 GB) |
| Зависание после U-Boot | Повреждённый образ в NAND — для разработки лучше перейти на SD |

### Что проверить после успешного boot log

| Проверка | Как |
|----------|-----|
| Объём RAM | Строка `DRAM:` / `mem=` в логе; ревизия C41 V1.2 может иметь 1 GB |
| Разметка NAND | `cat /proc/mtd` на штатном Linux |
| SD-слот | Режим SD + FAT с тестовым файлом, или команды `mmc` в U-Boot |
| Ethernet | `ip a`, ping — если штатный Linux поднимает сеть |

### Чего не делать при первом включении

- Не перепрошивать NAND, пока не сохранены boot log и `/proc/mtd`.
- Не включать режим **JTAG**, если кабель не подключён и нет образа для загрузки с ПК.
- Не подавать питание на случайные пины «наугад».

## Минимальный порядок действий

1. Подключить UART, терминал **115200**, включить запись лога.
2. Джамперы **NAND**, подать питание.
3. Сохранить лог → сравнить с `bootlog_stock_nand.log`.
4. Если Linux поднялся — снять `/proc/mtd`, `cmdline`, `version`.
5. Для своей прошивки — переключить на **SD**, не трогая NAND, пока образ не проверен.
